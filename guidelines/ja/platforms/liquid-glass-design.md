# Liquid Glass デザイン（Apple プラットフォーム）

## 判定

Liquid Glass は iOS/iPadOS 26+、macOS 26+、tvOS 26+、watchOS 26+ のシステムデザイン言語であり、iOS 27 / macOS 27 の世代で洗練・調整された。新しい Apple プラットフォーム向けプロジェクトは採用が必須で、本書は新しいアプリ UI を設計する前の必読である。既存の pre-iOS-26 アプリに移行の義務は課さない——旧アプリの改修は本書のスコープ外である。

システムのデフォルトをまず採用し、システム chrome が設計を表現できない箇所だけカスタマイズする。このマテリアルは現在も進化している（iOS 26.1 世代と iOS 27 でそれぞれ再調整された）。Apple の HIG を常に更新される信頼できる唯一の情報源とし、OS のメジャーリリースごとに再確認する。

## 二層モデル

- Liquid Glass は光を散乱ではなくリアルタイムで曲げて集束させる（lensing）動的マテリアルである。色調・影・ダイナミックレンジは背後の内容に合わせて継続的に適応する。
- UI は二層に分かれる：コントロールとナビゲーションからなる機能層（タブバー、サイドバー、ツールバー、ナビゲーションバー、メニュー）がコンテンツ層の上に浮く。コンテンツはガラスの下をスクロールし、ガラスがコントロールの可読性を保つ。コンテンツ層は Liquid Glass を適用してはならない領域である——不透明でも標準マテリアルでもよいが、ガラスは決して使わない。
- 二つのマテリアルファミリーが存在し、役割は入れ替わらない：Liquid Glass はコントロール／ナビゲーション層用、標準マテリアル（blur、vibrancy、厚みの階層）はコンテンツ層内部の構造用である。
- 小さなガラス要素は背景に合わせて明暗を反転させる。大きな表面（メニュー、サイドバー）は適応するが反転しない。要素はフェードではなく lensing の調節で出現する（materialize）。

## ガラスの居場所

- 機能層に属するもの：ナビゲーションバー、ツールバー、タブバー、サイドバー（iPad/Mac ではインセットとフローティング）、メニュー、sheet と action sheet、コントロールの一時的なアクティブ状態（slider・toggle は操作中にガラスを帯びる）、カスタムフローティングコントロール。
- コンテンツ層には決して置かない——アプリの背景、カード、テーブル／コレクションの内容はコンテンツ層に属し、Liquid Glass を一切使わない（HIG: "Don't use Liquid Glass in the content layer"）。唯一の例外はコンテンツ層コントロールの一時的なアクティブ状態である。
- ガラスの上にガラスは重ねない。要素がガラスの上に載るときは、フィル・透明度・vibrancy を使い、マテリアルの一部として読めるようにする。
- 下に屈折させるものが何もない場所にガラスを置かない——ガラスはコンテンツ層に寄り添うコントロールのものであり、静的なコンテンツ領域のものではない。
- ガラスは装飾ではない。特にスクロールエッジエフェクトは浮遊 chrome の下にコンテンツを溶け込ませるためのもので、飾りではない。

## バリアント：regular と clear

- regular がデフォルトである：背景をぼかして輝度を調整し、どんな内容にも適応し、どのサイズでも読める。文字の多い chrome（alert、サイドバー、popover）と、背景が可読性を損なう恐れのある場所では必ずこれを使う。
- clear は恒久的に透明度が高く、適応的な可読性の振る舞いを持たない。三条件すべてが成立する場合に限る：メディアリッチなコンテンツの上に浮いている；コンテンツ層が調光レイヤーで害を受けない；ガラス上のコンテンツが太字で明るい。
- clear が明るい内容の上に乗るとき、ガラスの下に約 35% の黒不透明度で調光レイヤーを置く。内容がすでに暗いなら省略する。
- 関連する要素間で regular と clear を混ぜない。

35% の調光値、三条件テスト、ティントの制限は Apple が現時点で公表しているデフォルト値と文脈テストである——従うが、永久のトークンとしてハードコードせず、メジャーリリースごとに HIG を再確認する。

## 色付けとカラー

- ガラス自体は固有の色を持たない。ティントは一つの色を、背後の明るさに応じたトーン列へ写像し（ステンドグラスの挙動）、コントラストを得られる。
- ティントは強調にだけ使う：主要アクションかステータス一つ。システムは prominent ボタンのガラスをアクセントカラーで染める。
- 多くのコントロールにティントを付けない。色はコンテンツ層に置く。背景が彩色なときはバーをモノクロにするか、判別しやすいアクセントを選ぶ。
- 小さなバーのシンボルとラベルはデフォルトでモノクロであり背景とともに反転する——反転に逆らう明暗固定の文字色を設定しない。

## 形状と同心性

- 三つの形状タイプ：fixed（一定の角丸半径）、capsule（半径 = 高さの半分。自然に同心であり、バー・slider・switch・グループ角丸のデフォルト）、concentric（内側の半径を親の半径からパディングを引いて導出し、システムが計算する）。
- ネストしたコンテナー（カードの中のアートワーク、バーの中のボタン）は同心形状にして内側の半径を自動計算させる。角を絞ったり広げたりしない。
- iPhone の画面端付近では capsule に追加マージンを設ける。iPad/Mac ではウィンドウ端と同心的に揃える。ネストしても単独でも使うコンポーネントは、フォールバック半径付きの同心形状にする。
- macOS 27 ではすべてのウィンドウが同じより小さい角丸半径になる——従来のウィンドウごとの半径は前提にしない。

## レイアウト：エッジツーエッジ

- 背景と全面ビジュアルはディスプレイ端まで広げ、スクロール可能な内容は浮遊 chrome の下へ続ける。システムのセーフエリア（Dynamic Island、カメラハウジング、各バー）を尊重し、iPad のウィンドウサイズ全域に対して設計する。
- スクロールエッジエフェクトが、浮遊ガラスとスクロール内容の間の硬い区切り線に取って代わる。soft は iOS/iPadOS のデフォルト（繊細な遷移）。hard は主に macOS 向き（テキスト系コントロール、ボーダーレスコントロール、固定ヘッダーの均一で不透明な境界）。ビューごとに一つ、split view の各ペインで高さをそろえ、重ねず、浮遊 UI がない場所では使わない。
- 内容がウィンドウ全幅を満たさないとき（サイドバー、inspector レイアウト）は background extension を使い、内容が chrome の下へ続いて見えるようにする。テキストとコントロールはその上に重ねて歪みを避ける。
- iOS 27：内容が浮遊バーの下をスクロールすると上部に均一なツールバーが現れる（標準ツールバーは自動）。iPhone アプリは iPad と iPhone Mirroring でリサイズ可能になる——サイズとアスペクト比の動的な範囲に対して設計し、固定レイアウトではなくツールバーのリフロー（オーバーフロー、優先度、ピン留め）を使う。

## アクセシビリティ

- システムコンポーネントは自動的に適応する——オプトインは不要：Reduce Transparency ではガラスがよりすりガラスになり背景をより隠す。Increase Contrast では要素がほぼ黒／白になりコントラスト境界が付く。Reduce Motion では弾性・液体の挙動が抑制される。カスタムガラスは三設定と Dynamic Type すべてでテストする。
- コントラストの下限を満たす：17 pt 以下の文字は 4.5:1、18 pt 以上または太字は 3:1。ライトとダークの両方で検証し、Increase Contrast 有効時により高いコントラストの配色を提供する。
- iOS 27 ではユーザーがガラス外観を調整するスライダー（ウルトラクリア ↔ 完全ティント）が加わり、macOS 27 では "show borders" のアクセシビリティ値が得られる。ユーザーや OS バージョンをまたいで一つの固定レンダリングを前提にしない。
- Reduce Motion 下のモーフと液体モーション：スプリングを引き締め、ジェスチャに直接追従させ、フェードを優先し、ブラーの出入りのアニメーションは避ける。

## iOS 27 の変化

- マテリアルが再調整された：背後の複雑な内容の拡散が改善し、暗い縁と明るい鏡面ハイライトが付いた。Liquid Glass 利用済みのアプリは再コンパイルなしで新しいレンダリングを得る。
- ユーザーがガラス外観をシステム全体で調整できる（ウルトラクリア ↔ 完全ティント）——設計は全区間に耐えねばならない。
- サイドバーは iPad と Mac で画面端まで広がり、アイコンがアクセントカラーを取り戻す。macOS/iPadOS ではメニューアイコンがデフォルトで非表示になる（主要アクションは API で表に出す）。
- ウィンドウが明確な非アクティブ外観を持つ（カスタムビューは `appearsActive` に従う）。macOS ではカスタムガラスがインタラクティブになる（マウス最適化）。
- アプリアイコンのレンダリングがシャープになり半透明感が減る。Icon Composer は多層 Liquid Glass アイコンと屈折アノテーションを設計でき、旧 OS でのプレビューにも対応する。

## するべきこと・してはいけないこと

| するべきこと                                                              | してはいけないこと                                           |
| ------------------------------------------------------------------------- | ------------------------------------------------------------ |
| ガラスは浮遊コントロールとナビゲーションに限定する                        | コンテンツ層のビュー（テーブル、背景、カード）にガラスを使う |
| デフォルトは regular。文字の多い chrome では特に                          | 可読性やコンテンツ層が害になりうる場面で clear を使う        |
| clear はメディアリッチな内容の上だけ。明るい背景では約 35% の調光レイヤー | 関連要素で regular と clear を混ぜる                         |
| ティントは主要アクション一つにだけ                                        | 多くのコントロールやシンボルにティントを付ける               |
| シンボルはモノクロのままシステムに任せる                                  | 反転に逆らう明暗固定の文字色を設定する                       |
| capsule・同心形状を使い、半径はシステムに計算させる                       | 角を絞る・広げる・ネストした角丸を手計算する                 |
| コンテンツはエッジツーエッジ、スクロールエッジエフェクトで融合            | ガラスの上にガラス。バー背景・境界線・区切り線の再追加       |
| ビューごとに一つのスクロールエッジエフェクト                              | スクロールエッジエフェクトを装飾に使う                       |
| 単一モードのアプリでも明暗両方のカラーを用意する                          | Increase Contrast や iOS 27 の外観スライダーを無視する       |
| Reduce Transparency、Increase Contrast、Reduce Motion をテストする        | カスタムガラスをデフォルト設定だけで検証して出荷する         |
